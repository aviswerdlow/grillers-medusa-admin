# UPS price acceptance (launch #331 candidate)

This candidate consumes weight/calendar/packing PRs 33–35 and locally integrates the exact A1 safety candidates PR 28 (`46a661a`) and PR 29 (`1e5932a`). Merge their ancestors first. It is not permission to activate pricing, publish policies, provision keys, migrate data or charge a customer. Strategy #331 and #329/#357 remain the acceptance record.

## Contract

A published `cold-chain-setting.ShippingPricingPolicy` must contain an explicit approval, revision, UTC effective interval (start inclusive, end exclusive), USD currency, positive maximum customer shipping charge, the CMS table's price basis, and `finalShipping=retain_accepted`. There are no operating numeric defaults. This implements one selectable rule, not Peter's approval of it. An alternate formula or final-charge rule needs his decision and implementation before activation.

Forecast confidence/markup produces a freight pricing basis; its raw estimate and adjustment stay separate. WWEX supplies freight. A CMS fallback is a configured customer tariff and cannot establish actual carrier cost. With `cmsFallbackBasis=freight_only`, each source adds the same approved box/ice plan once. With `inclusive_customer_tariff`, a CMS tariff already includes packaging, so it is not added again; physical costs remain recorded. The full pre-promotion charge must stay below the approved limit or the option is unavailable. A free-shipping promotion is applied by Medusa afterward; the $350/$500, exclusions, pickup credits and Atlanta rules are not replaced here.

Native Medusa rates options *before* validating shipping-method data. `calculatePrice` returns an opaque authenticated quote token alongside the calculated amount. The storefront sends the displayed token when selecting a service. Both provider calculation and data validation consume that exact token, bound to cart, address, item quantities/prices, physical plan, current approved policy and a 15-minute lifetime. A second carrier lookup cannot silently change it. Completion freezes shipping revenue, tax and discount separately from freight/packing costs, and checks the exact loaded cart again.

The new price envelopes use AES-256-GCM and purpose-separated keys. Deployment requires `GP_SHIPPING_PRICE_ACTIVE_KEY_ID` and a protected JSON map in `GP_SHIPPING_PRICE_KEYS_JSON` from key ID to strong random secret (at least 32 characters). No development fallback is used. Keep every historical decryption key while an accepted order or backup needs it; rotating the active ID can leave old keys available. Do not rotate/remove these with login JWT keys. Key values and raw envelopes do not belong in issues, logs or this repository. Provisioning is a separate authorized release action, owned by Avi.

A completed order's accepted policy does not expire when a later CMS policy changes. The retain-accepted rule preserves customer shipping through packing, including free shipping and item/order credits. New card charging and invoice release stop when required pricing/carrier data is unavailable. The A1 recording-recovery path can still retrieve an already-settled PaymentIntent without requiring a new carrier quote; it cannot create a replacement PI when the known ID is absent. A1 attempt claiming, idempotency, fulfillment guards and durable outbox remain intact.

Final cost metadata records the actual carrier quote and package rows separately; unknown procurement costs and carrier bills remain null for #369. Invoice and card release use the same accepted-price check. Old orders lacking this contract require a reviewed migration/amendment, not inferred approval. Customer-requested amendments remain #368's workflow and must preserve original snapshots before proposing new terms. This candidate must be integrated with its calendar, inventory and staff-authority candidates before rehearsal.
