# Receiving adjustment fixture contract (#321)

The synthetic vectors in `integration-tests/incoming-stock/receiving-adjustment.fixtures.ts` define the required result of a future source-agnostic native adjustment adapter. Each source system/reference pair must have one durable adjustment record tied to the native inventory item and location. A retry after an unknown response, including a second consumer, must return the recorded result without increasing stock or transferring a commitment again.

The fixture set covers: an unknown-result retry; two consumers of one source; short and zero final receipts; two distinct rolling partial deliveries; a receipt already included in an approved baseline; and an unresolved baseline overlap that must remain blocked. Existing PostgreSQL tests also prove that the current #364 ledger stages zero/short receipts once, rejects a second final receipt, and leaves stock application pending. The vector test checks that expected native and reservation quantities balance. **Neither test executes a native Medusa adjustment.** The rolling-partial vector is a future acceptance target; today's final-only staging path rejects its second delivery.

For the implementation, run every vector against real Medusa inventory levels and reservation items in an isolated PostgreSQL fixture. Record the source-to-adjustment and commitment-transfer IDs, then assert stocked quantity, reserved quantity, remaining commitments, affected-order exceptions, and eligible restock events after each attempt. Test a response loss after native commit, simultaneous consumers with separate connections, and a transaction failure before commit. Keep an included-baseline receipt from increasing native stock twice, and block an unresolved overlap. A restock event requires newly usable free stock; a pending receipt, invoice, or fully committed receipt is not a restock.

No production receiving source, unit, usable-time rule, baseline inclusion decision, operator grant, or send owner is chosen here. #359 must record those answers before connecting the adapter. This PR makes no production write path and does not close #321.
